## 提示词正文（从这行开始复制）

```
你是一名用 ManimCE（from manim import *）做小学数学讲解短视频的老师兼程序员。
请把下面这道题重做成一条可以直接发布到抖音和微信视频号的竖屏讲解视频。
观众是小学五六年级学生和辅导作业的家长，他们是真的不会这道题，
目标只有一个：看完一遍就能自己说出解法。不许跳步，不许先写公式再解释，
不许假设观众懂"单位「1」"这个词——第一次出现时必须用一句话解释。

==================== 本题（写死，不要改数） ====================
题目：某公司由于客服人数较少，满意度只有 3/5。后面引进了智能客服单独服务，
满意度是原来的 6/5。现在采用智能客服与人工客服双重服务，满意度又提高了 1/4。
那么现在的满意度是多少？
正确答案（先独立验算再写代码，不一致就停下来报错）：
3/5 × 6/5 = 18/25；18/25 × (1 + 1/4) = 18/25 × 5/4 = 90/100 = 9/10。
化小数交叉验算：0.6 × 1.2 = 0.72，0.72 × 1.25 = 0.9 ✓
关键一跳：「又提高 1/4」的单位「1」是当下的 18/25，不是最初的 3/5。
典型错答（解说里要点名排除）：若把第二个 1/4 当成原来 3/5 的 1/4，
会错算成 87/100。必须说清为什么错：提高的 1/4 是对着"现在的"满意度算的。
================================================================


1. 第 4 幕硬伤：步骤标题"第 4 步 · 列式求解"压住了第一行算式
3/5 × 6/5 = 18/25 的分子。修法：算式组整体下移，给步骤标题留出
0.9 个单位以上的净空；或者把步骤标题改成右上角小药丸标签。
渲染后必须抽查第 4 幕定格帧，确认零重叠。
2. 第 3 幕粉块歧义：v1 里代表"18/25 的 1/4"的粉块画在旧条末格，
生长后还留在原地，而真正新增段是另一个颜色的块，两个粉色意思不同。
修法：粉块必须真的动起来——从旧条末格脱离、平移到条的末端，
落位后才变成新增段；增量段全片只用一种粉色、只出现在末端；
生长完成前旧条末格的粉块淡出，不许两种粉同时在场。
第一次生长的增量段（0.6→0.72）也不许再画成叠在条上的独立紫块，
直接让条本身变长、末端用粉色描边标出新增部分即可。
3. 第 1 幕标签贴边："3/5 原来的满意度"的分数分子贴着 5 格条下沿。
修法：标签整体下移 0.3 个单位，或把分数移到条的右侧。
4. 第 4 幕缺半步：从 18/25 × (1+1/4) 直接跳到 = 18/25 × 5/4，
中间必须单独占半行写出 1 + 1/4 = 4/4 + 1/4 = 5/4。
5. 第 5 幕排版不统一：第三行验算用了斜杠写法 9/10，与前两行真分数不一致，
改成真分数排版。


1. ManimCE 语法，不许改用 ManimGL。只写一个 Scene 类，类名保持
SmartServiceSatisfaction；背景色 #0B1026；答案先写进代码开头变量
（Fraction）并用 assert 代回验算，上屏数字只能引用变量。
2. 竖屏 1080×1920，30fps，高质量导出（最终 mp4 体积不低于 8MB，
平台还会二次压缩，源文件必须留余量）。总时长 50~60 秒。
注意：是重排版，不是把 1280×720 的横屏画面裁剪成竖屏——
0~1 标尺保持横向全宽、居中放在画面 15%~70% 高度区，字号按竖屏放大。
3. 必须有配音和字幕，二选一的交付方式：
a) 用 TTS 按下方逐字稿生成配音（普通话，语速约每分钟 230 字），
与动画逐句对齐后混入成片，并烧录同文案字幕；
b) 若环境无法生成配音，则交付：无声成片 + 同名.srt 字幕文件 +
逐字稿.txt，并在交付说明里明确写"配音需在剪映里补"，
不许假装已经有配音。
4. 字幕：画面下方、距底部约 18% 高度处（避开抖音/视频号的标题区和进度条），
白色粗体、黑色描边，每行不超过 16 个字，当前句的关键词
（如"单位「1」变了""不是原来 3/5 的 1/4"）用黄色。
5. 安全区：顶部 8% 不放重要信息，右侧 12% 不放文字（避开点赞按钮列），
底部 22% 只放字幕不放公式。主体内容必须分布在画面 15%~70% 高度区，
禁止像 v1 横屏版那样上下大片留白。
6. 字号（按 1080 宽折算）：主标题 ≥64px，步骤标题 ≥54px，
正文与解说 ≥46px，公式 ≥56px，任何文字不小于 40px。
7. 配色语义沿用 v1（条件 #00D9FF｜关键与答案 #FFC24B｜变化 #FF6B9D｜
验算 #2ED3A6｜正文 #FFFFFF｜次要 #A9B4D8），同一颜色全片只表达同一个意思。
粉色 #FF6B9D 全片只表示"新增的那一段"，不许再挪作他用。


幕 1（0~5 秒）钩子 + 题目：先上大字提问"满意度只有 3/5，上了智能客服，
居然能涨到 9/10？关键在第二个 1/4。"然后 5 格满意度条（3 格填充）+
三条条件逐条入场 + 加粗问句"现在的满意度是多少？"
解说：满意度只有五分之三，上了智能客服，居然能涨到十分之九？
关键，就藏在第二个四分之一里。
幕 2（5~13 秒）建模型：链条图 [3/5] →(×6/5)→ [?] →(×(1+1/4))→ [?]，
只建模不计算；底部翻译句"「是原来的 6/5」→ 乘 6/5；
「又提高 1/4」→ 乘（1+1/4）"；再加一句防误读小字
"6/5 是跟原来比的倍数，不是占总数的 6/5"。
解说：先别算。第一句话，"是原来的五分之六"，就是乘五分之六。
第二句话，"又提高四分之一"，就是乘一加四分之一。注意啊，
这个五分之六，是跟原来比的倍数，不是占总数的五分之六。
幕 3（13~30 秒）关键一跳：0~1 标尺上条生长 3/5→18/25；
把 18/25 的条切成 4 等份，粉块从末格脱离、平移到末端落位变成新增段，
条长到 9/10；点破句上屏"单位「1」变了：这次的 1/4，是 18/25 的 1/4，
不是原来 3/5 的 1/4"；错答 87/100 用灰色小字划掉带过。
解说：先看第一步，条从五分之三长到二十五分之十八。现在看第二步，
提高的四分之一，是对着谁算的？是对着现在的二十五分之十八！
把它切成四份，其中一份，就是新长出来的这一段。
要是拿原来五分之三的四分之一来算，就会错成一百分之八十七。
幕 4（30~40 秒）列式求解：算式逐行左对齐入场，每行只完成一步，
必须含 1 + 1/4 = 5/4 这一行；本行关键数用黄色；步骤标题与算式零重叠。
解说：列式就是两步：五分之三乘五分之六，得二十五分之十八；
一加四分之一等于四分之五，再乘上去，九十分之一百，约分得十分之九。
幕 5（40~48 秒）验算：10 格条摆出 9/10 可数；逆向除回两条打勾；
合理性"9/10 没超过 1"打勾。
解说：验算一下：十分之九除以四分之五，回到双重服务前；
再除以五分之六，回到最初的五分之三，都对上了。
幕 6（48~55 秒）答案卡 + 互动：居中圆角框"答：现在的满意度是 9/10"；
下行方法口诀"单位「1」变了没有？先看提高是对着谁算的"；
最后一行小字提问"如果第二句话改成「提高了 1/5」，答案是多少？
评论区试试"。
解说：记住这个办法：看到"又提高几分之几"，先问一句，
是对着谁提高的。单位「1」找对了，题就做对了一大半。


1. 分数一律用真实分数排版（MathTex）；环境没有 LaTeX 时先报错说明，
不许把 "3/5" 斜杠形式当成品交。
2. 渲染完成后，抽取 2s、8s、16s、24s、33s、38s、45s、52s 共 8 帧自检：
无重叠、无出界、字幕不被底部安全区切掉、上下不是大片空白、
第 3 幕同一时刻只有一种粉色在场、数字与第一步的验算结果一致。
发现问题改代码重渲染，不许带着问题交付。
3. 交付物：带配音字幕的 mp4 + 更新后的.py 源码 + 分镜表 + 逐字稿。
同步更新 README：补齐渲染依赖（LaTeX、Noto Sans SC 字体、
manim 版本 pin）、新成片的时长与分辨率、v1→v2 改了哪几处。
4. 交付说明写明：时长、分辨率、配音是已合成还是待补、关键一跳在第几幕。
```

## 发布配套（不用喂给 zcode，这是 cai 自己发的时候用）

- **封面**：用幕 1 钩子帧，大字两行「满意度 3/5 → 9/10 / 关键在第二个 1/4」。
- **抖音标题**：满意度 3/5，上了智能客服能涨到 9/10？坑在第二个 1/4 #小学数学 #分数应用题 #单位1
- **视频号标题**：辅导孩子先问一句：这个 1/4，是对着谁算的？

- **发布时间**：19:00~21:30 家长辅导时段；同一条竖屏成片两个平台共用。
