+ `SmartServiceSatisfaction.mp4`（37.8 秒，1280×720 @30fps，无音轨）

## 结论

**数学全对，结构是对的，但这版不能直接发抖音/视频号。** 有 1 处画面硬伤
（第 4 幕算式被步骤标题压住）、1 处教学表达风险（第 3 幕粉块会让人看错），
外加无配音无字幕、横屏 16:9 三个发布级问题。修完再发，见 `PROMPT.md`（竖屏 v2）。

## 数学核对 ✓

- 3/5 × 6/5 = 18/25 ✓；18/25 × (1 + 1/4) = 18/25 × 5/4 = 90/100 = 9/10 ✓
- 化小数交叉验算：0.6 × 1.2 = 0.72，0.72 × 1.25 = 0.9 ✓
- 代码里 `Fraction` + `assert` 代回验算与上述一致，答案变量是唯一数字来源。
- 典型错答对照：若把第二个 1/4 当成原来 3/5 的 1/4，会得到 87/100——
  v1 没有点名排除这个错答，v2 提示词里要求解说把它点破。

## 做得好的地方

1. **主线选对了**：单位"1"连乘 + 0~1 标尺，标尺全程不动、动的只有满意度条，
   关键一跳（"又提高 1/4"的单位"1"是当下的 18/25，不是最初的 3/5）是这道题
   真正的坑，抓得准。
2. **验算扎实**：10 格条把 9/10 摆出来可数 + 两次逆向除回打勾 + 合理性检查
   （9/10 没超过 1），三重验算，比只写一行算式可信得多。
3. **代码干净**：`Fraction` 验算、语义配色固定、6 幕分镜与 README 对得上，
   不是写死数字的演示稿。

## 必须修的问题（按严重程度）

### 1. 硬伤：第 4 幕算式被步骤标题压住了（约 24~28 秒）

抽帧 f25、f28 都能看到：左上角"第 4 步 · 列式求解"几个字直接盖在第一行
算式 `3/5 × 6/5 = 18/25` 上，分子 3、6、18 都被字压住一半。这不是转场残影，
是定格帧就这样。原因在代码里：`eqs` 用 `to_edge(LEFT, buff=0.85).shift(UP*0.2)`，
和 `step()` 的左上角位置撞了。v2 要求：算式组整体下移、给步骤标题留出
0.9 个单位以上的净空，渲染后必须抽查第 4 幕定格帧确认无重叠。

### 2. 教学风险：第 3 幕的粉色块会让人看错（约 15~21 秒）

- 18/25 的条被切成 4 等份后，那个粉色的"1/4 块"画在**旧条的最后一格**
  （0.54~0.72 的位置），生长之后它还留在原地，而真正新增的一段
  （0.72~0.90）是另一个颜色偏紫的方块。最终画面是三段：青 / 亮粉 / 暗紫，
  两个粉色表达的不是同一个东西——观众很容易把中间那块亮粉当成"新增的部分"，
  位置却对不上。
- 第一次生长的增量段（0.6→0.72）也被画成一个叠在条上的独立紫块，
  和条本身是两种颜色，读起来像"又多了一块"，而不是"条变长了"。
- v2 要求：粉色 1/4 块要**真的动起来**——从旧条末格脱离、平移到末端，
  落位后才变成新增段；增量段只用一种颜色，且只在末端出现。生长完成前，
  旧条末格的粉块必须淡出，不许两种粉同时在场。

### 3. 无配音、无字幕（全片）

`ffprobe` 确认成片只有视频流、没有音轨。37.8 秒全程静默，关键句
"单位「1」变了"只以文字出现。给学生和家长看的讲解视频，这一点是发布级硬伤，
不是加分项。v2 要求 TTS 配音 + 烧录字幕，做不到配音就交 srt + 逐字稿并注明。

### 4. 横屏 16:9，不适合抖音/视频号竖屏信息流

成片是 1280×720 横屏。发到抖音/视频号会被压成小窗，手机上公式更难读。
而且即使当横屏看，内容也只占画面中间一条带：第 3 幕（f12、f16、f21）、
第 4 幕（f25、f28）、第 5 幕（f32）上下都有大片空白。v2 改为 1080×1920
竖屏重排版，不是简单裁剪：0~1 标尺保持横向全宽、字号按竖屏放大、
主体放在画面 15%~70% 高度区。

### 5. 两处小缺口（讲法上的）

- **1 + 1/4 = 5/4 这一步没展开**：第 4 幕直接从 `18/25 × (1+1/4)` 跳到
  `= 18/25 × 5/4`，没写 `1 + 1/4 = 4/4 + 1/4 = 5/4`。对不会的学生来说，
  这是第二个容易卡住的点。v2 要求单独占半行写出来。
- **"6/5"没做防误读**：只写了"是原来的 6/5 → 乘 6/5"，没说清 6/5 是
  "跟原来比的倍数"，不是"占总数的 6/5"。学生容易疑惑"满意度怎么能超过 1"。
  v2 要求解说里加一句点破。
- 次要：第 1 幕 "3/5 原来的满意度"的分数分子贴着 5 格条的下沿（f05、f08、f10），
  第 5 幕第 3 行验算用了斜杠写法 `9/10`、和其他两行的真分数排版不一致。
  v2 一并修掉。

  在新机器上会直接失败。v2 要求 README 补齐系统依赖与 manim 版本 pin。
- 成片 mp4（1.4MB）直接进 git 目前没问题；视频再多时建议上 Git LFS。
